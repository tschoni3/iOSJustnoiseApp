## Inspection interference correction — September 20

The preceding ADB UI-tree inspection used `uiautomator dump`, contrary to the
existing owner-device protocol in `ANDROID_PLAY_IMPLEMENTATION.md` and the Gate 0
README. Owner approval for ADB navigation did not establish that this particular
inspection mechanism was non-interfering. This was a testing error, not grounds to
weaken the app's recovery checks or blame the app for a newly reproduced failure.

Android's official `UiAutomation` documentation confirms that the default
connection suppresses other Accessibility services; service preservation requires
`FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`. The published legacy shell wrapper
uses the default `connect()` call. This is a strong explanation for a recovery
warning during the dump but an ordinary idle screenshot after the dump exits.
The inspected app marks the service disconnected on unbind and refreshes its
heartbeat on reconnect, consistent with this sequence. Exact Samsung command
internals/lifecycle logs were not captured, so device-specific causality is an
inference, not a fully instrumented proof.

The warning/tree mismatch above is therefore **test-contaminated**, not an accepted
new product defect. The History screenshots still directly show the rendered
aggregate/day detail, but this pass supplies no clean restriction/service-readiness
evidence. The statement that the inspection was state-neutral must be qualified:
no explicit permission/settings change was issued, but automation may have
temporarily disconnected the service. Existing persisted historical totals were
not deliberately changed; no active-session test ran in this pass.

No further UI-tree dumps or instrumentation will run on the paired A16. A prominent
guard was added to `AGENTS.md` to surface the existing protocol before UI inspection.
The next clean observation uses only screenshot plus scoped passive service state.
During this investigation the wireless transport disappeared; a fresh `adb devices
-l` returned an empty device list. No re-pairing or network setting change was made.
Clean current-state confirmation remains pending device reconnection.

Sources: [Android UiAutomation](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES),
[AOSP legacy shell wrapper](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-31/+/refs/heads/main/com/android/uiautomator/core/UiAutomationShellWrapper.java).
